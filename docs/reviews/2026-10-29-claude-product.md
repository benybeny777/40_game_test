# タスクバー百鬼行：商用品質レビュー（ゲームディレクター／有料プレイヤー視点）

## 総評

仕様、データ、描画コード、画像を静的に確認しました。ゲームの実行、ブラウザー操作、ファイルの編集はしていません。そのため、以下の指摘は「コードと画像からの観察」と「計算による試算」です。体感や手触りは実プレイで確かめる必要があり、その箇所は【要実プレイ】と書いています。

**結論：保存の堅さや仕組みの数は揃っています。ただ、980円で売るゲームの中心であるべき「拾った装備で組み方が変わる楽しさ」がまだ機能していません。** 戦闘も装備も育成も失敗時の立て直しも自動で、しかもしばらく壁がありません。そのため最初の数時間、プレイヤーの判断が結果に影響しません。17人の個性もまだ見た目と名前で止まっていて、戦い方の差になっていません。

良い点もはっきりあります。仲間17人の輪郭の描き分けは強く（`docs/images/characters.png`）、ポップアップ鬼（ブラウン管）、招き猫もどき、呪いのフィギュアなどの敵の発想は覚えてもらえる力があります。レア度の「並・上・特上」も和風で魅力があります。素材は良いので、遊びの仕組みが追いついていない状態です。

## 優先度付きの問題点

### P0-1 戦利品の興奮がない（装備を探すゲームとして成立していない）

**根拠（静的）**
- 通常敵のドロップ率は1体3%（`src/core/data/items.ts:56`）。2時間のsimでは1110撃破・B32（`docs/VALIDATION.md:31`）なので、1時間あたり約17個です。
- 武器の対象ジョブを17人全員から抽選しています（`src/core/progress/profile.ts:71` の `jobs: partyOrder`）。出撃中3人向けの武器は、ドロップ全体の約7%（40%×3/17）にすぎません。
- レア度の重みは 極1.8 / 伝説0.2 / 神話0.03（`items.ts:14-16`）。試算では、通常100階の踏破（sim約300分）までに拾う約85個のうち、極は約1.5個、伝説は約0.2個です。**伝説を一度も見ずに通常モードを終えるのが普通**になります。
- アイテムLvは階数そのもので、上限は60です（`profile.ts:95`、`items.ts:36`）。B60以降は装備が強くならず、**修羅のB1に入るとアイテムLv1に戻ります**。難易度の報酬倍率は小判と経験値にしか効きません。
- 追加効果12種はすべて汎用の数値です（`items.ts:19-32`）。組み方を変える装備は神話の4種だけです。防具名3種・お守り名3種は全ジョブ共通で、Lv60を超えると「・改弐…」と付くだけです（`items.ts:53-54`、`progress/items.ts:30`）。
- ドロップ演出は、極以上が同じ文言のバナー（`scene.ts:183`）だけです。神話を拾っても特別な演出はありません。

**変更案**
1. 武器の対象ジョブ抽選を出撃中に寄せる（例：出撃3人70%／控え30%）。
2. アイテムLvを難易度で連続させ、上限60を撤廃する（例：アイテムLv＝階＋難易度×100）。
3. 序盤から極・伝説に出会えるよう、レア度の重みか保証枠を再調整する（例：各ボス撃破で特上以上を確定、10階ごとの初回撃破で極以上を確定）。
4. 追加効果に「ジョブのスキルを変える」系を6〜8種加える。新しい仕組みではなく、既存のパラメーターを変えるだけのものにする（例：居合の倍率+、地雷の範囲+、結界の継続+）。
5. 伝説以上は専用の止め演出（帯の一瞬の暗転と光柱）を入れる。

**受入条件**（seed 1〜20のsim）
- 開始10分以内に出撃3人の装備更新が1回以上ある：90%以上のseed
- 最初の極：中央値45分以内
- 通常100階までに伝説：1個以上
- 難易度が変わってもドロップのアイテムLvが下がらない（テストで確認）

### P0-2 自動装備と自動の立て直しが判断を消している

**根拠（静的）**
- 自動装備は既定でON（`profile.ts:46`）。正の評価差があれば、17人のうち誰にでも黙って装着します（`items.ts:157-175`）。
- 評価式 `power`（`items.ts:119`）が、巨神の断ち刃の「遅いが重い」などのトレードオフを代わりに判断してしまいます。
- 3連続で全滅すると自動で一つ前の階へ戻り、2回クリアで再挑戦します（`GAME_SPEC.md:57`）。失敗さえプレイヤーの判断を求めません。
- 2時間のsimで全滅0（`VALIDATION.md:31`）。**最初の2時間に壁がなく、編成も装備も結果に影響しません。**

**変更案**
- 自動装備は「特上以下・同じ系統の単純な上位互換」だけにする。極以上と固有装備は自動装着せず、「鑑定待ち」に入れて、パネルを開いたときに「装備する／しない」の比較カードを1枚出す。自動装備の機能自体は残す（確定仕様のため）。
- 全滅して自動で一つ前の階へ戻るときは、帯とパネルに「何が足りないか」の診断を1行出す（例：「前衛の被ダメージが大きい → タンクか回復役を」）。

**受入条件**
- 極以上の自動装着が0件（テスト）
- 既定編成・手動操作なしで、B10ボスの初回勝率が40〜70%
- 推奨の一手（診断どおりの交代か装備）を打てば90%以上で勝てる（sim）
- 初回の全滅で必ず診断文が出る

### P0-3 17ジョブが戦い方として描き分けられていない

**根拠（静的）**
- 奥義17種のうち11種が「敵全体に攻撃力×2〜3.5」（`jobs.ts` の issen、mijin、lovebomb、oatari、souchou、kyouka、houjou、knifecurtain、hyakki、junkstorm、ooichiban）です。
- 支援系の効果が体感しにくい大きさです。ギャルのパッシブは攻撃+5%、殿は間隔−5%、巫女は被ダメージ−5%（`jobs.ts:55,67,115`）。
- ジョブ同士の相互作用は、ダメージや間隔の乗算が重なるだけです。「この2人だと何かが起きる」という連携が存在しません。
- 経験値は出撃3人だけに入る（確定仕様）一方、出遅れた仲間の追いつき手段がありません。B30でLv1の控えを出すのは自殺行為なので、**実質的に最初の3人で固定**されます。

**変更案**
- 新しい仕組みを足すのではなく、既存の状態を「タグ」にして参照させる。既存の注目マーク・鈍足・低HP・挑発・結界・被弾を使い、連携を5組明示する。例：
  - 忍者の会心がギャルの注目マーク付きの敵に+
  - スケバンの追い込みがガリ勉の鈍足中の敵にも適用
  - 番長の反撃が巫女の結界中は2倍
- 奥義11種は数値の上乗せではなく、副効果をロールの核にする。例：番長＝全員分を引き受ける、農民＝貫通の一列、パチプロ＝出目で全体の効果が変わる。
- 支援パッシブは「目に見える数値」まで上げる。
- 追いつき手段（**確定仕様と両立する案・要確認**）：経験値は出撃者だけのまま、出撃者の平均Lvより低い仲間に獲得経験値×3の補正を付ける。

**受入条件**
- 17人それぞれに「その人がいないと崩れる局面」が少なくとも1つある
- 敵・ボスの対処ヒントでジョブ名が挙がる。17人全員が、少なくとも1つのヒントに登場する
- 控えをB30で出撃させてから15分以内に、平均Lv−3以内へ追いつく（sim）

### P1-4 100階が同じ景色と同じ敵の繰り返し

**根拠（静的）**
- 通常敵9種＋ボス3種が5階ごとに循環します（`stages.ts:14`、`themeSpan:5`）。100階で同じ並びを約6.7周し、大ボス戦は10回すべてが3体の使い回しです。
- 最初に会う大ボスは招き猫大将（B10は区域2）で、大鬼はB20が初登場です。
- 強敵（精鋭）はHP×1.8・攻撃×1.15の数値強化だけです（`dungeon.ts:17`、`world.ts:134`）。
- 区域名が3か所で食い違っています。
  - データ：夜の街道／シャッター商店街／電脳街（`stages.ts:5-7`）
  - 表示と背景：古の地下墓地／朽ちた商街／禁術の書庫（`dungeon.ts:4`）
  - パネルの見出し：「裏・東京をゆく」（`panel/index.ts:119`）
- その結果、「禁術の書庫」に羽虫やブラウン管の鬼が出ます。

**変更案**（敵を大量に増やす前にやること）
- 世界観を一つに決め、区域名・敵・背景を揃える。案：「東京の地下に開いた黄泉。地下墓地→埋もれた商店街→廃データの書庫」とすれば、電脳系の敵も書庫に自然に収まる。
- 強敵に「階の特性」を1つ付ける（例：回避↑、後衛を狙う、回復半減）。編成判断を求める効果に限る。
- 25階ごとに区域を変えて背景のパレットを変える。
- ボスは3体のまま、周回ごとに技を1つ追加する。

**受入条件**
- 3か所の区域名が一致する（テスト）
- 10階ごとの精鋭特性が少なくとも8種あり、各特性に対処ヒントが付く
- B1〜B50で「前の10階と同じ敵の並び・同じ技」が続かない

### P1-5 帯の視認性と打撃の手応え

**根拠（画像）**
- `play-strip.png`：暗い背景の上で、紺のサムライと黒い忍者の輪郭が背景に溶けています。
- ダメージ数値「13 / 11 / 46」が縦に重なり、小さく読みにくいです。
- 戦闘は画面幅の約37%に収まり、残りは空いています（仕様どおり）。
- `party-atlas.png`：2行目と4行目がほぼ待機姿と同じです。地雷系とオタクの攻撃姿は腕を出すだけで、予備動作が弱いです。
- 透過の縁に色のにじみが見えます（例：パチプロの赤い縁、`enemy-attack.png` の鬼火・招き猫大将の周り）。
- 敵は線が太く陰影が細かいのに対して、味方は粗い点で、画風の密度が揃っていません。

**変更案**
- 味方に明るい1ドットの外枠（リムライト）を付ける。
- 会心は数値を大きく・色を変え、同じ瞬間の数値は横にずらす。
- 縁のにじみは素材処理で除去する。
- 支援系の攻撃姿は「掲げる→放つ」の2段にする。

**受入条件**
- 表示倍率100%・150%の両方で、17人全員が3つの背景すべての上で判別できる（実画面キャプチャを並べた一覧で人が確認）
- 縁のにじみ0ピクセル（不透明部と透明部の境界の検査）

【要実プレイ】打撃の重さ、止めの長さ、帯を長時間眺めたときの疲れ。

### P1-6 最初の5分とUIの優先順位

**根拠**
- 初回の案内処理がありません（renderer内に初回・案内系の処理なし）。ヘルプは辞書型で、セーブ障害やSteam取引の説明が多くを占めます（`help.ts:63-66, 166-176`）。
- 試算では、最初の5分は約45撃破・ドロップ1〜2個・B2付近で、ボスにも宝箱にも会わず、判断は0回です。
- パーティ画面は、出撃3人のカードの直下に同じ3人の詳細を繰り返しています（`play-panel.png`）。
- スマホでは「Resume / Return to town」のボタンが戦闘表示に重なっています（`mobile-en.png`）。
- 英語表示に「battle171 EXP」という文の連結ミスがあります（スマホ画像。現行版で残っているかは要確認）。
- `docs/images/` の画像は、v0.6で削除した上部の言語切替ボタンが写っていて古いです。販促にそのまま使えません。

**変更案**
- 初回の流れを決めておく。B1の精鋭は出撃者向けの上の武器を確定で落とし、パネルを開くと「比べる→装備」を1回だけ案内する。B3で能力振りを1回案内する。
- タブ構成を「編成／装備／ダンジョン」を主、「図鑑／道場」を副、「ストア／ヘルプ／設定」を末尾に並べ替える。

**受入条件**
- 新規セーブで、5分以内にプレイヤー自身の判断（装備・振り分け・交代のどれか）が1回以上起きる
- 初回案内は3ステップ以内で、スキップ可能・再表示可能

【要実プレイ】初見の人がパネルを開く動機を持てるか。

### P1-7 音がない

**根拠：** ヘルプに「音は鳴りません」（`translations.ts:47`）とあります。一方で `GAME_SPEC.md:139` の画面一覧には「音」があり、仕様と実装が食い違っています。

**提案：** 常駐ゲームなので、Windowsの既定はミュートでよいと思います。そのうえで、伝説以上・ボス撃破・レベル到達だけを鳴らす控えめな通知音（オプトイン）と、スマホ向けの効果音一式を入れることを推奨します。

**受入条件**
- 音量設定が保存される
- 既定値がプラットフォームごとに仕様に書かれる
- 鳴る出来事が1時間あたり10回以下（帯の常駐でうるさくしない）

**要判断：** 既定でONにするかOFFにするか。

### P2-8 やり込みと終盤

**根拠：** 深淵は無限に続きますが、アイテムLv60・キャラLv60で頭打ちです。道場の費用も100レベルで固定されます（`profile.ts:173`）。終盤の伸びが「数字が増えるだけ」で、新しい判断が生まれません。

**変更案（P0-1とP1-4の延長で足りる）**
- 深淵は階ごとに精鋭特性が2つ重なる
- 深淵限定の固有装備を2〜4種追加する
- 自己ベストとして到達階＋使った3人を記録する

### P2-9 動作の重さ（常駐ゲームとしての品質）

**根拠：** 旧版の30分試験で、working set 584MiB、CPU累積207.6秒／1780秒（`VALIDATION.md:58`）。1コア換算で平均約12%です（共有ページの重複を含むため参考値）。

**提案：** 一日中常駐させるとノートPCの電池に響く水準です。省電力モード（前面が全画面のとき・バッテリー時は描画を10fps程度へ）の目標値を決めることを推奨します。

【要実測】現行exeでの長時間計測。

## 名称の評価（ブランド設計として）

検索の事実や商標の空き状況は断定しません。調査が必要です（`docs/IP.md:36`）。

**現名「タスクバー百鬼行／Taskbar Hyakkiko」の弱点**
1. **意味が逆向き**：百鬼行は妖怪の行列です。主人公は妖怪を倒す人間3人なので、題名が敵側を指しています。
2. **端末に縛られる**：スマホ版にタスクバーはありません（`GAME_SPEC.md:151`）。題名が商品の一部と矛盾します。
3. **読みが定まらない**：「百鬼夜行」の省略形の造語で、読みが揺れます（ひゃっきこう／ひゃっきぎょう）。英語圏では "Hyakkiko" から意味も読み方も推測できません。
4. **「Taskbar」は一般名詞**で、それ自体を独自の名前として持ちにくいです。

**反対に一番強い資産**は「社会のはみ出し者17人が地下の黄泉へ降りていく」という絵です。地雷系、パチプロ、源じい、ガリ勉はそれだけで覚えてもらえます。

**方向性の案**（すべて仮。商標調査が前提です）
- **A：はみ出し者たちこそが百鬼、と読み替える。** 「はぐれ百鬼」系。今の題名の「百鬼」を活かし、意味の逆転を解消します。
- **B：舞台で立てる。** 「ヨミクダリ／Yomi Descent」系。黄泉の迷宮と100階を降りる流れが一語で伝わります。
- どちらの場合も「タスクバー」は副題・機能の説明へ下げる（例：「〇〇 ～タスクバーの百鬼退治～」）。

**比較の基準**
- 読みが一意に定まる
- 英語でも発音できる
- 主題（17人・降下・妖怪）の少なくとも1つを担う
- 端末に依存しない
- ロゴとアイコンで絵になる

**関連する名前のリスク：**
- 日本語のジョブ名「ホームレス」は、英語表記がすでに "Vagabond"（`en-game.ts:485`）です。日本語も「放浪者」「拾い屋」などに揃えると、ストア審査と海外での受け取られ方のリスクが下がります。外見の確定仕様はそのまま維持できます。
- パチプロの「確変・大当たり」は、年齢区分の申告でギャンブル表現として問われる可能性があります。要確認です。

## 最初の改善バッチ（推奨）：「拾う→比べる→選ぶ→壁を越える」

装備を探すゲームの中心の流れを1本通すことを目的とし、新しい機能は足しません。

1. **装備抽選**：武器を出撃中に寄せる、アイテムLvを難易度で連続させる、序盤のレア度保証（P0-1の1〜3）
2. **自動装備を特上以下に限定**し、極以上は鑑定カードで本人が選ぶ（P0-2）
3. **B10ボスを最初の壁に調整**し、全滅時に診断の1行を出す（P0-2）
4. **初回の流れ**：B1の確定ドロップと3ステップの案内（P1-6）
5. **伝説以上の専用演出**（P0-1の5）

**このバッチの完了条件：**
- 上記の受入条件（sim 20seed＋テスト）をすべて満たす
- そのうえで実プレイ30分で「自分の判断で勝てた」瞬間が2回以上あることを、人が確認する

**次のバッチ：** ジョブの連携と奥義の差別化（P0-3）→ 世界観の統一と精鋭特性（P1-4）→ 帯の視認性と音（P1-5・P1-7）

## 先に決めていただきたいこと

1. 自動装備を特上以下に限定してよいか（機能はONのまま残します）
2. 控えの追いつき補正（出撃者だけが経験値を得る仕様とは両立します）を入れてよいか
3. 世界観の軸を「東京の地下の黄泉」に統一し、区域名を揃えてよいか
4. 音の既定値（WindowsはOFF・スマホはONを推奨）
5. 名称の方向性（A：はぐれ百鬼系／B：舞台系）と、日本語の「ホームレス」表記を変えるか

確認範囲：仕様4文書、HANDOFF、VALIDATION、データ定義（jobs / balance / enemies / dungeon / stages / items / progress / attributes）、`progress/items.ts`・`progress/profile.ts`、`scene.ts`・`help.ts`の一部、画像11枚（`docs/images` と atlas 4枚）。音、帯の打撃感、長時間の動作は実プレイ・実測が未確認です。
