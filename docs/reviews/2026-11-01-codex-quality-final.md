# Codex ゲーム品質・最終差分レビュー

2026-11-01。対象は `5380593` からの今回の作業差分（0.7.2）。製品コードの編集・追加起動・再ビルドは行わず、現在のソースと関連テストを再読した。区域lootコアはこの担当自身が実装したため、同箇所を独立した第三者レビューとは呼ばない。敗北記録・画面・移動操作は別担当の実装をレビューした。

## 判定

**今回のコード・ゲーム体験の改善を承認する。既知の承認阻害欠陥は見つからなかった。** 最終配布ビルドとその実行結果は、この文書の作成時点では未確定であり、配布物の合格を先取りしない。以前の0.7.1承認を今回の検証へ流用しない。

今回の価値はバグ修正だけではない。「負けた理由を見て編成や装備を変更する」「欲しい装備部位から周回先を選ぶ」という判断が、観測データと実際の抽選へ接続された。新しい敵や階層数の追加を必要とせず、既存17人と装備選択を使う理由が増えている。

## 確認した根拠

- `core/progress/defeat.ts` / `core/game.ts`：実stepの正の被ダメージ、死亡、蘇生、wipeを順に処理。実出撃3人を対象とし、予約編成を混ぜない。wave/town境界で一時集計を消し、直近敗北だけを保存する。致命打を観測できなければnullとし、推測しない。
- 敗北validatorは旧版の未設定/nullと不正な記録を区別。人数、重複ジョブ、負値・非有限値、順位、敵と技能の組合せを検証し、原因のフィールドをエラーへ残す。返値は既知フィールドから構築する。
- `panel/defeatReview.ts`：倒れた順・被ダメージ・致命打から編成と防具へ進める。突破実績のある記録を折り畳み「再訪」とする。これは敗北後に突破した証明とは言わず、既存クリア実績として表示する。現在地・予約済み・別迷宮への再挑戦操作を抑止する。
- `data/loot.ts` / `progress/items.ts` / `profile.ts`：実探索階から区域を決め、難易度補正後の装備ランクと分離。墓地の防具、商街の武器、書庫のお守りの重みを2倍とし、全slotの出現、希少度抽選、神話固有、指定slot、出撃者向け武器配分を維持する。
- `panel/dungeon.ts`：区域傾向だけでなく、浅い階への移動による基礎性能低下の傾向とランダム幅も説明。出やすさを確定報酬や確率2倍と誤称しない。
- `dungeonTravel.ts` / `panel/index.ts`：未送信の階層入力は再描画とTab移動で消えず、成功した移動後は下書きを解除する。予約はホストのworld.pendingを共通Viewへ渡して表示する。
- `core/game.ts`：現在地の再指定でウェーブを巻き戻さない。全滅時の自動周回が既存の移動予約を上書きしない。`tests/core/game.test.ts` は同難度・別難度の予約保持と、walking/battle/wipe/stageClearの現在地無変更を扱う。

## 最終小修正の再確認

`core/game.ts` の全滅時処理を再読した。明示的な移動予約があるときは予約先を保持するだけでなく、緊急の自動周回を利用者の周回設定へ戻し、`autoFarmClears` も0にする。これにより、周回OFFで移動した先が意図せず周回になる経路を防ぐ。手動周回ONでは `autoLoop` 自体がfalseなので設定を保持する。

同難度・別難度の移動予約、到着後のloop一致、手動周回ONの保持を扱う追加テストも確認した。統合担当から関連43テスト成功の報告あり。この修正に新たな承認阻害欠陥は見つからず、コード承認を維持する。修正後の全体検証・最終配布物は引き続き統合担当の結果待ち。
