# 02 帯の描画（M2）

## 1. ドットの倍率とウィンドウの高さ

M0は帯の高さを `STRIP_HEIGHT = 96`（DIP）で固定している。表示倍率150%の環境では1ドット＝4.5物理ピクセルとなり、ドット絵がにじむ。M2で次の方式に置き換える。

- **1ドットを、整数の物理ピクセル（`dotPx`）で描く**。DIPではなく物理ピクセルで考える。
- 自動の場合：`dotPx = max(2, round(2.5 × scaleFactor × sizeMul))`。`sizeMul` は設定の表示サイズ（小0.75／中1／大1.25）。
  - 例：100% → 3、125% → 3、150% → 4、200% → 5。
- 帯の中身は2つの領域に分ける：
  - **遊ぶ領域**：高さ32ドット。キャラ・地面・HPバー。
  - **上の余白**：高さ `headroomDip = 72`。ダメージ数字・ドロップの跳ね・ツールチップ・奥義の文字を出す。普段は透明で、クリックは透過する。
- ウィンドウの高さ（DIP）＝ `ceil(32 × dotPx ÷ scaleFactor) + headroomDip`。割り切れずに余った端数は、遊ぶ領域の上側の透明な部分に回す（下端はworkAreaの下端に揃える）。
- 計算は `src/main/windows/placement.ts` に置き、テストする。結果は `strip:layout` で帯へ送る（04-panel-ipc.md §2）。
- 帯は1つのウィンドウのまま。ツールチップ用に別のウィンドウを作らない。

## 2. 描画の手順

```
オフスクリーンCanvas（幅 W ドット × 高さ H ドット。下の32行が遊ぶ領域、その上が余白）に1:1で描く
   ↓ drawImage で dotPx 倍に拡大（imageSmoothingEnabled = false）
表示用Canvas（物理ピクセル：innerWidth × devicePixelRatio）
```

- 表示用Canvasの `width/height` は物理ピクセル、CSSの大きさはDIP。`devicePixelRatio` が変わったら作り直す。
- 論理の幅 `W = floor(物理の幅 ÷ dotPx)`、高さ `H = floor(物理の高さ ÷ dotPx)`。余りのピクセルは右端と上端の透明として残す（拡大した画像は左下に揃えて置く）。
- ツールチップと奥義の日本語の文字は、DOM（DotGothic16、CSSで `image-rendering` は指定しない）で上の余白に出す。数字と英字は3×5ドットのビットマップ文字を、オフスクリーンに描く。
- 描画する層（下から）：地面 → 影 → 地雷 → 敵 → 味方 → 弾 → エフェクト → HPバー → 数字 → 右端のHUD。

## 3. 縦の配置（遊ぶ領域、ドット）

| 行 | 内容 |
|---|---|
| 0〜3 | 状態のアイコン（4×4：攻撃UP、回避UP、確変、執着など） |
| 4〜5 | HPバー（幅16×高さ1＋黒い縁）。奥義ゲージは味方だけ、HPバーの下に1行の金色 |
| 6〜29 | キャラ（24×24の枠、足元が29行目） |
| 30 | 地面の線 |
| 31 | 影 |

- 背景の明るさに関係なく見えるよう、すべてのスプライトに1ドットの暗い縁（パレットの`a`）を付ける。
- 設定「地面の帯」がオンのとき、24〜31行目に不透明度35%の暗い帯を敷く（明るいウィンドウの上で読みやすくする）。

## 4. 横の配置

- パーティの基準点（シミュレーションのx=0、先頭の足元）を、画面のx＝`W × 0.15 + 72`ドットに置く（最後尾のx=−72が画面幅の15%の位置に来る）。シミュレーションのxはそのまま足すだけ（拡大しない）。
- 敵の出現位置 x=+160 が画面の外（右端）を超える場合でも、そのまま描く（右から歩いてくる）。画面の幅がそれより狭い場合は、出現時に8コマかけて半透明から現れる演出にする。
- 右端のHUD：幅64ドットの枠に「1-3 ⑦/10」と小判の数。日本語のエリア名は、マウスを乗せたときのツールチップで出す。

## 5. 演出（スナップショットとイベントから作る）

- スナップショットは10Hzで届く。描画は、直近の2つのスナップショットの間を補間する（100ms遅れで描く）。補間するのは `x` だけ。
- ユニットごとに描画用の状態を持つ：`anim`（walk／idle／attack／skill／hit／down）、`frame`、`flashUntil`、`fade`。
  - フェーズが walking なら味方は walk、それ以外は idle を基本にする。
  - `attack` → attackを1回再生して基本に戻る。`skill`／`ultimate` → skillを再生。
  - `damage` → 白く光らせる（100ms）＋1ドット後ろへずらす（100ms）。数字を出す。
  - `death` → downを再生。敵は500msかけて消える。味方は灰色にしてその場に残る。`revive` で元に戻す。
- 数字：白（通常）、黄（会心、1ドット大きく揺らす）、緑（回復）、灰「MISS」。600msで6ドット上がって消える。同時に出すのは30個まで（超えたら古いものから消す）。
- 弾：`projectiles` の `launchTick` と `hitTick` から位置を補間して描く。種類ごとのスプライト（手裏剣は回転、ハートは上下に揺れる、玉は小さな放物線）。
- 地雷：点滅（爆発の1秒前から速く）。爆発は5コマの円。
- 奥義：帯の上の余白に、ジョブの色の横線と技名のDOM文字を600ms出す。サムライの一閃は遊ぶ領域を1コマだけ白くする。**画面を揺らさない**。
- 確変：当たりのとき、パチプロの頭上に虹色の「確変」アイコンを10秒。大当たりは出目を3つのドット数字で回してから止める。
- ドロップ：`drop` で、レア度の色のアイコンが上の余白まで跳ねてから、右端のHUDへ吸い込まれる（800ms）。
- 地面：walking中は地面の模様（草・小石・提灯の影など、エリアごと）を、`20 × (1 + 道場の移動速度)` ドット/秒で左へ流す。

## 6. スプライトの形式

### 6.1 テキストの定義（当面の正本）

`assets/sprites/src/<name>.sprite.txt`：

```
name: samurai
size: 24x24
anchor: 12,23          # 足元の中央（左上が0,0）
palette: base32
anim idle fps=4 loop
frame
........................
.........aaaa...........
（24行）
frame
...
anim attack fps=10 once
frame ...
frame = attack#0       # 同じコマの使い回し
```

- 1文字＝1ドット。`.` は透明。それ以外の文字は `assets/palettes/base32.txt` の記号（`a`〜`z`、`0`〜`5` の32種類）に対応する。
- パレットファイルは `a #1a1c2c 縁・影` のように「記号 色 用途」を1行ずつ書く。
- すべて**右向き**で描く。敵は描画時に左右を反転する。
- 必要なアニメ：キャラは idle(2)・walk(4)・attack(3〜4)・skill(4)・hit(1)・down(2)。雑魚は idle(2)・walk(2)・attack(2)・hit(1)・down(2)。ボスは雑魚＋skill(4)。
- ジョブごとの見分け方は、`docs/images/game-concept.png` を参考にする（DESIGN.md §10）。

### 6.2 読み込み

- 帯は、Viteの `?raw` でテキストを読み込み、起動時に `ImageData` → `ImageBitmap` に変換する（ビルドの手順やPNGファイルを増やさない）。
- 読み込み側の型は1つにしておき、後でPNG＋JSON（Asepriteの書き出し形式）を足せるようにする：

```ts
interface SpriteSheet { image: ImageBitmap; frameW: number; frameH: number; anchor: [number, number]
                        anims: Record<string, { frames: number[]; fps: number; loop: boolean }> }
```

- テキストを読む関数（`parseSprite`）は純粋な関数にして `src/core/` の外の `src/renderer/strip/sprites/` に置き、Vitestでテストする（コマの大きさの不一致、知らない記号、anchorの範囲外をエラーにする）。
- `pnpm sprites:preview` で、全スプライトを4倍に拡大して並べたPNGを `.dev-data/preview/` に書き出す（Nodeの `zlib` を使い、依存を増やさない）。Codexが自分で描いたドット絵を目で確認するために使う。

## 7. マウス

- M0の当たり判定（DOMのボタン）を、Canvas上の当たり判定の一覧に置き換える。一覧は毎フレーム作り直す：味方・敵（スプライトの縁ではなく、24×24の枠）、右端のHUD。
- マウスが当たり判定の上に乗ったときだけ `pointer(true)`。外れたら `pointer(false)`。上の余白のツールチップ自体には当たり判定を付けない（触れようとすると透過が切れて邪魔になる）。
- 乗せたとき：味方は「名前 Lv HP スキルの残り秒」、敵は「名前 HP 特性」、HUDは「エリア名 ステージ 周回のオン／オフ」。
- クリック：味方 → 管理パネルをそのジョブのページで開く。敵とHUD → ステージのタブ。右クリック → M0と同じメニュー。

## 8. 性能

- 描画は `requestAnimationFrame` で回し、前回の描画から `1000 ÷ fpsCap` ms 経っていなければ描かない。
- 非表示・一時停止・最小化のときはループを止める。一時停止中は最後の画面を残す。
- 帯ウィンドウは `backgroundThrottling: false` を指定する（フォーカスを持たないため、描画が間引かれるのを防ぐ）。実際に間引かれるかを実画面で確かめ、結果をHANDOFFに書く。
- 毎フレームのメモリ確保を減らす：数字・パーティクルは配列を使い回す。

## 9. 受入条件（M2）

- 表示倍率100%と150%で、ドット絵がにじまない（スクリーンショットを拡大して、1ドットが同じ大きさの正方形になっていることを確認）。150%の環境は今のPCで確認できる。100%は設定を変えて確認するか、未確認として記録する。
- 5人と敵が歩き・攻撃・被弾・倒れるところが見える。数字・HPバー・ドロップが出る。
- 透明な部分の後ろのアプリをクリックでき、キャラの上ではツールチップが出る。
- 30fpsの上限を守り、一時停止中は描画が止まる。平常時のCPUとメモリをタスクマネージャーで5分間見て、HANDOFFに記録する（目標：CPU 2%以下、メモリ250MB以下。超えた場合は値と原因の見立てを書く）。
- `parseSprite` と `placement` の計算のテストが通る。
