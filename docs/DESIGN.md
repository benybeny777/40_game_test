# 設計書：タスクバー常駐 和風放置RPG（仮題「タスクバー百鬼行」）

作成：2026-10-20　対象：Codexによる実装

## 0. この文書の使い方

- 実装は「13. マイルストーン」の順に進める。各マイルストーンの受入条件を満たしてから次へ進む。
- 数値（ステータス・成長率・ドロップ率など）はすべて初期値。`src/core/data/` に集約し、コード中に直書きしない。調整はデータだけで行えるようにする。
- 「決定」と「未決定」を区別する。未決定事項（15章）は勝手に確定させず、仮実装する場合はHANDOFF.mdに「仮」と記録する。
- 作業ルールはAGENTS.mdに従う。GitHub Actionsは使わず、検証はすべてローカルで行う。

## 1. コンセプト

Windowsのタスクバーのすぐ上にある細い帯の中を、5人の和風パーティが自動で進み、妖怪と戦って戦利品を拾う放置RPG。作業の邪魔をしないことを最優先にする。

- 参考にしたのは「Taskbar Hero」のようなタスクバー常駐型の放置RPG。名称・画像・UI配置・数値はコピーしない。
- 遊び方：普段は横目で眺めるだけ（数秒）。たまに管理パネルを開いて装備やスキルを整える（1〜3分）。
- 世界観：現代と和風が混ざった「裏・東京」。夜の街道から始まり、商店街・電脳街・ネオン街へと進む。敵は妖怪と、現代の怪異。
- 見た目：基本はドット絵。帯の中は低解像度のドット表示を整数倍に拡大して描く。

## 2. 決定事項

| 項目 | 決定 |
|---|---|
| ジャンル | タスクバー常駐型の放置オートバトルRPG（2D） |
| 対象環境 | Windows 11（Windows 10でも動けばよい。macOSなどは対象外） |
| 実装方式 | Electron + TypeScript + Vite。帯はCanvas 2D、管理パネルはDOM |
| パッケージ管理 | pnpm（PCに導入済み：Node v24 / pnpm 10） |
| テスト | Vitest（ロジック）、実画面での目視確認（表示・操作） |
| 初期ジョブ | サムライ、忍者、地雷系、オタク、パチプロ（5人） |
| 表示文 | 日本語 |
| 音 | 初期状態はミュート（常駐ゲームのため） |

採用理由：PCにNodeとpnpmがあり、追加の導入が少ない。透明な最前面ウィンドウとクリックの透過がElectronで安定して実現できる。ロジックを純粋なTypeScriptに分ければ、Codexがテストで検証しやすい。Godotなどのゲームエンジンは未導入で、この規模なら必要ない。

## 3. 技術構成

### 3.1 プロセスとウィンドウ

```
[main process]  ── シミュレーション（10Hz固定）・セーブ・トレイ・ウィンドウ管理
   │ IPC（状態のスナップショット＋イベント）
   ├─ [帯ウィンドウ]   Canvas描画。透明・枠なし・最前面・タスクバーに表示しない
   └─ [管理パネル]     通常のウィンドウ。DOMのUI。必要なときだけ開く
```

- シミュレーションはmainプロセスで動かす。状態の正本は1つだけにし、帯を隠していても進行・セーブが続くようにする。
- 帯ウィンドウの設定：`frame:false`、`transparent:true`、`alwaysOnTop:true`、`skipTaskbar:true`、`focusable:false`、`resizable:false`、`hasShadow:false`。
- 配置：`screen` の `display.bounds` と `display.workArea` の差からタスクバーの辺と高さを求める。初期値は「タスクバー直上」で、帯の下端をworkAreaの下端に合わせる。タスクバーが自動的に隠れる設定でbounds＝workAreaになる場合は、画面の下端に合わせる。
- 「タスクバーに重ねる」配置は設定で選べるようにするが、タスクバーより前面に出し続けられるかは要検証とする（初期値にはしない）。
- クリックの透過：既定は `setIgnoreMouseEvents(true, { forward: true })`。帯側でマウス位置の当たり判定を行い、キャラ・UI上にあるときだけIPCで透過を解除する。透明部分の後ろにあるアプリは常にクリックできること。
- トレイアイコン：表示／非表示、管理パネルを開く、一時停止／再開、終了。
- 多重起動は `requestSingleInstanceLock` で防ぐ。2回目の起動では管理パネルを前面に出す。
- 解像度の変更・モニターの抜き差し・タスクバーの移動（`display-metrics-changed` など）で帯を再配置する。

### 3.2 安全設定

- `contextIsolation:true`、`nodeIntegration:false`、`sandbox:true`。rendererへは型付きのpreload APIだけを公開する。
- 外部URLを読み込まない。素材・フォントはすべて同梱する。

### 3.3 性能の目標

- 帯の描画は最大30fps。変化がないとき・非表示のときは描画を止める。
- 目安：CPU使用率は平常時2%以下、メモリ使用量は250MB以下。M2で実測し、HANDOFF.mdに記録する。

### 3.4 フォルダ構成

```
src/
  core/            # 純粋なTS。Electron・DOMに依存しない
    sim/           # world.ts, combat.ts, ai.ts, skills.ts, formulas.ts, rng.ts, events.ts
    data/          # jobs.ts, enemies.ts, stages.ts, items.ts, balance.ts（数値の正本）
    save/          # schema.ts, migrate.ts
  main/            # Electron main
    paths.ts       # セーブ・設定・ログのパスを定義する唯一の場所
    windows/       # strip.ts, panel.ts, placement.ts
    tray.ts, ipc.ts, loop.ts, saveStore.ts
  preload/         # strip.ts, panel.ts（contextBridge）
  renderer/
    strip/         # Canvas描画、スプライト、エフェクト、当たり判定
    panel/         # DOMのUI（タブ構成）
  shared/          # IPCの型・チャンネル名
assets/
  sprites/         # スプライト（テキスト定義 or PNG＋JSON）
  fonts/  palettes/
tools/             # sim-runner.ts, build-sprites.ts
tests/             # Vitest
docs/              # この設計書、CREDITS.md（素材・フォントの出典とライセンス）
```

## 4. 画面

### 4.1 帯（メイン画面）

- 論理解像度：高さ **32ドット**。幅＝画面幅 ÷ 表示倍率。
- 表示倍率：整数倍（自動／1／2／3）。自動の場合は、OSの表示スケールを考慮して実ピクセルで高さが約64pxになる倍率を選ぶ。`imageSmoothingEnabled=false` で描画する。
- 縦の配置（ドット）：0〜5行目はHPバー・ダメージ数字・状態アイコン、6〜29行目はキャラ（24ドット）、30行目が地面、31行目は影。
- 横の配置：パーティは帯の左寄り（左端から約15%の位置）に、前衛を右にして隊列を組む。敵は右から現れる。背景は描かない（透明）。地面は薄い線か、透明度のある帯で表す（設定で切り替え）。
- 右端：エリア名・ウェーブ（例「街道 1-3 ⑦/10」）・小判の所持数を、小さなビットマップ文字で表示する。
- 操作：
  - キャラにマウスを乗せる → 名前・Lv・HP・スキルの再使用までの時間をツールチップで表示
  - キャラを左クリック → 管理パネルをそのキャラのページで開く
  - 帯の上で右クリック → 簡易メニュー（パネル／一時停止／隠す）
  - それ以外の場所はクリックを透過する

### 4.2 管理パネル

- 通常の枠付きウィンドウ（初期値960×600、サイズ変更可）。DOMで作り、ドット風のCSSにする。
- タブ：**パーティ**（隊列の並び替え、Lv、ステータス）／**装備**（所持品、装備、自動売却）／**スキル**／**道場**（永続強化）／**ステージ**（エリアの選択、周回の設定）／**図鑑**（敵・装備）／**設定**。
- 起動時、オフライン報酬がある場合は「おかえり」画面を出す。

### 4.3 フォント

- パネル：DotGothic16（SIL OFL）を同梱する。
- 帯：数字と短い英数字は自作の3×5ドットのビットマップ文字を使う。日本語は帯にはほぼ出さず、ツールチップではパネルと同じフォントを使う。
- 出典とライセンスを `docs/CREDITS.md` に記録する。

## 5. ゲームの流れ

1. パーティが右へ歩く（背景はないので、地面の模様と敵の出現で前進を表す）。
2. ウェーブに出会う（敵1〜5体）。立ち止まって自動で戦う。
3. 勝ったら経験値と小判を獲得し、一定確率で装備が落ちる。ドロップは帯の上でアイコンが跳ね、自動で回収される。
4. 10ウェーブ目はボス。倒すと次のステージが解放される。
5. **周回モード**：オンなら今のステージを繰り返す。オフなら解放済みの最も先のステージへ自動で進む。
6. **全滅**：3秒後にそのステージのウェーブ1から再開する。失うものはない。同じステージで3回続けて全滅したら、自動で周回モードに切り替え、パネルに「強化しよう」と案内を出す。
7. **オフライン報酬**：起動していなかった時間（上限8時間）×（直近10分の平均獲得量）×0.5。経験値・小判だけで、装備はレア度の低いものを少数。

構成：エリア（全5を予定、初期実装は1〜3）× 各5ステージ × 各10ウェーブ。エリア5の最後まで約10〜15時間を目安とする（調整はsim-runnerで行う）。

## 6. パーティとジョブ

### 6.1 ステータス

| 略号 | 名前 | 意味 |
|---|---|---|
| HP | 体力 | 0で戦闘不能。戦闘終了時に30%回復し、ウェーブの間の移動中にも少しずつ回復する |
| ATK | 攻撃力 | |
| DEF | 防御力 | |
| INT | 攻撃間隔 | 通常攻撃の間隔（秒）。小さいほど速い |
| CRI | 会心率 | 会心ダメージは既定で1.5倍 |
| EVA | 回避率 | |
| LUK | 運 | ドロップ率・小判・パチプロの抽選に影響する |

- 能力値(Lv) ＝ 基本値 ×（1 + 成長率 ×（Lv − 1））＋ 装備 ＋ 道場。INTは成長しない（装備と効果だけで変わる）。
- 隊列：5枠。先頭（右端）が前衛。近接攻撃は先頭の敵だけを狙える。遠隔攻撃は敵を誰でも狙える（既定では一番近い敵）。
- 敵の狙い：既定は先頭のキャラ70%、ほかのキャラ30%（「挑発」で変わる）。

### 6.2 ジョブ一覧（Lv1の基本値）

| ジョブ | 役割 | HP | ATK | DEF | INT | CRI | EVA | LUK | 射程 | 武器 |
|---|---|---|---|---|---|---|---|---|---|---|
| サムライ | 前衛・攻撃と盾 | 120 | 12 | 8 | 1.2 | 10% | 5% | 5 | 近接 | 刀 |
| 忍者 | 速攻・回避 | 80 | 9 | 4 | 0.7 | 15% | 20% | 8 | 遠隔 | 忍具 |
| 地雷系 | 呪い・範囲・ハイリスク | 90 | 14 | 3 | 1.5 | 5% | 5% | 5 | 遠隔 | 呪具 |
| オタク | 回復・応援 | 85 | 6 | 4 | 1.3 | 5% | 5% | 10 | 遠隔 | ペンライト |
| パチプロ | 運・経済・一発逆転 | 85 | 10 | 4 | 1.1 | 8% | 5% | 30 | 遠隔 | 玉入れ |

成長率：HP 0.10、ATK 0.09、DEF 0.07、CRI・EVA・LUKはLvごとに＋0.2（%またはポイント）。

### 6.3 スキル

各ジョブに 通常攻撃 ／ スキル（Lv1、再使用時間で自動発動）／ パッシブ（Lv5）／ 奥義（Lv15、奥義ゲージ）がある。奥義ゲージは、与えたダメージと受けたダメージで溜まり、満タンで自動発動する。

**サムライ**
- 通常「斬撃」：ATK×1.0。
- スキル「居合」（8秒）：次の一撃が必ず会心になり、ATK×2.5。
- パッシブ「仁王立ち」：先頭にいるとき、敵に狙われる確率が＋20%、受けるダメージが−15%。HPが50%以下になるとATK＋30%。
- 奥義「一閃」：敵全体にATK×3.0。画面を一瞬だけ白く光らせる（揺らさない）。

**忍者**
- 通常「手裏剣」：ATK×1.0。HPが一番低い敵を狙う。
- スキル「影分身」（12秒）：3秒間、回避率＋50%。分身を2体、半透明で描く。
- パッシブ「急所突き」：HPが30%以下の敵への会心率＋25%。
- 奥義「微塵隠れ」：敵全体にATK×2.5。そのあと2秒間は無敵。

**地雷系**（量産型・地雷系ファッションの呪術使い。表現は「重い愛」の可愛さに寄せる。16章を参照）
- 通常「病みハート弾」：ATK×1.0。当てると「執着」を付ける（その敵が受けるダメージ＋15%、5秒、重ねがけしない）。
- 固有ゲージ「情念」：0〜100。地雷系自身や仲間がダメージを受けると溜まる（受けたダメージ ÷ 最大HP × 100 × 0.5）。
- スキル「地雷設置」（10秒）：一番前の敵の足元に地雷を置く。踏まれるか3秒たつと爆発し、範囲にATK×2.5。
- パッシブ「重い愛」：情念が50以上のとき、ATK＋25%、受けるダメージ＋10%。
- 奥義「激重ラブボム」：敵全体にATK×（2.0 ＋ 情念 ÷ 50）。情念は0に戻る。

**オタク**
- 通常「ペンライト投げ」：ATK×0.8。
- スキル「差し入れ」（9秒）：HPの割合が一番低い仲間を、ATK×3.0＋最大HPの10%だけ回復する（エナドリの演出）。
- パッシブ「推しへの愛」：戦闘開始時に、仲間全体のATK＋10%（そのウェーブの間ずっと）。図鑑に初めて載る敵からのドロップ率＋20%。
- 奥義「全力応援」：仲間全体のHPを30%回復し、8秒間 攻撃間隔−20%。

**パチプロ**
- 通常「玉はじき」：1〜3発をランダムに撃つ。1発あたりATK×0.5。
- スキル「確変チャレンジ」（10秒）：当たる確率＝1/8＋LUK×0.1%（上限1/3）。当たれば10秒間、仲間全体の攻撃間隔−30%・獲得小判＋50%。外れたら小判を少し獲得する。
- パッシブ「期待値計算」：獲得小判＋15%、ドロップ率＋LUK×0.05%。
- 奥義「大当たり」：ルーレットの演出のあと、敵全体にATK×N（Nは1〜7。7が出る確率を上げるLUKの補正あり）。7なら小判のボーナス。
- 乱数はシミュレーションのシード付き乱数だけを使う。実際のお金や課金のくじは作らない。

### 6.4 経験値

- 次のLvまでの経験値 ＝ floor(20 × Lv^1.6)。Lvの上限は初期実装で50。
- 経験値はパーティ全員で同じ量を得る（戦闘不能のキャラも得る）。

## 7. 戦闘の計算

- シミュレーションは100msごとの固定ティックで進める。乱数はシード付き（mulberry32など）。同じシード・同じ入力なら必ず同じ結果になること。
- ダメージ ＝ max(1, floor(ATK × 倍率 × 100 ÷ (100 + DEF × 2) × 乱数(0.9〜1.1) × 会心 × 効果補正))
- 回避の判定は命中のたびに行う。回避したら「MISS」と表示する。
- 状態の効果は、種類・強さ・残り時間・発生源を持つ共通の構造で表し、同じ種類は重ねがけせず上書きする。
- シミュレーションは描画用のイベントを出す：`attack`、`damage`、`heal`、`miss`、`skill`、`ultimate`、`buff`、`death`、`waveStart`、`waveClear`、`drop`、`levelUp`、`bossAppear`。

## 8. 敵とステージ

### 8.1 強さの伸び方

ステージの通し番号を s（1始まり）とすると：HP＝基本値×1.18^(s−1)、ATK＝基本値×1.12^(s−1)、DEF＝基本値×1.10^(s−1)、小判・経験値＝基本値×1.15^(s−1)。ボスはHP×8、ATK×1.5。

### 8.2 エリア（初期実装は1〜3）

| エリア | 雑魚 | ボス |
|---|---|---|
| 1 夜の街道 | 提灯お化け（標準）、河童（硬い）、鬼火（速い・遠隔） | 大鬼 |
| 2 シャッター商店街 | 唐傘おばけ（回避）、化け猫（素早い2回攻撃）、招き猫もどき（倒すと小判が多い） | 招き猫大将 |
| 3 電脳街 | バグ精霊（倒すと分裂）、呪いのフィギュア（後衛を狙う）、ポップアップ鬼（自爆） | 電脳九尾 |
| 4 ネオン街（予定） | 酔いどれ天狗、ぬらりひょん | 未定 |
| 5 終電の高架下（予定） | 未定 | 未定 |

実在する地名・店名・メーカー名・作品名は使わない。

敵の特性はデータで組み合わせる：`ranged`（遠隔）、`fast`（速い）、`armored`（硬い）、`evasive`（回避）、`split`（分裂）、`backline`（後衛を狙う）、`explode`（自爆）、`goldBag`（小判が多い）。

## 9. 戦利品・装備・経済

- 通貨は小判（1種類）。素材などの追加は未決定。
- 装備欄：武器・防具・お守りの3つ。武器はジョブ専用、防具とお守りは誰でも装備できる。
- レア度：並（灰）／上（緑）／特上（青）／極（紫）／伝説（金）。ドロップの比率は初期値 70／22／6／1.8／0.2%。LUKなどの補正を受ける。
- 付加効果：レア度に応じて0〜3個。ATK%、HP%、DEF%、攻撃間隔−%、CRI、会心倍率、EVA、LUK、獲得小判%、スキル再使用−% から抽選する。値の範囲は `items.ts` で決める。
- 所持の上限は100個。自動売却（指定したレア度以下）と自動装備（総合値が上がる場合）を設定でオン／オフできる。
- 道場（永続強化。小判で買う）：全体ATK、全体HP、移動速度、オフライン報酬の上限時間、ドロップ率。費用は購入するたびに1.5倍ずつ上がる。
- 転生（やり直しで永続ボーナスを得る仕組み）は未決定。

## 10. ドット絵の仕様

- パレット：32色の固定パレット（自作するか、利用条件が明確な公開パレットを使う。出典をCREDITSに記録する）。
- 大きさ（ドット）：キャラ 24×24（体は約16×24）、雑魚 24×24、ボス 48×32。足元の中央を基準点にする。
- アニメーション：待機2コマ、歩き4コマ、攻撃3〜4コマ、スキル4コマ、被弾1コマ、戦闘不能2コマ。8fps。
- ジョブの見分け方（シルエットで判別できること）：
  - サムライ：ちょんまげか結い髪、刀、紺の着物
  - 忍者：黒装束、赤いマフラー（なびかせる）
  - 地雷系：ツインテール、黒とピンクの服、大きなリボン
  - オタク：眼鏡、リュック、ペンライト（光の色が変わる）
  - パチプロ：サングラス、柄シャツ、玉の入った箱
- 素材の形式：
  - **当面はテキストで定義する**。`assets/sprites/src/*.txt` に、パレット記号を並べた文字の配列でコマを書く。`tools/build-sprites.ts` でPNGのスプライトシートとJSON（コマの大きさ・アニメ名・コマ番号・fps・基準点）に変換する。Codexがドット絵を直接書け、差分もレビューしやすい。
  - 後で、AsepriteなどのPNGとJSONに置き換えられるよう、読み込み側は「PNG＋JSON」の形式だけを前提にする。
- エフェクト：ダメージ数字（白／会心は黄／回復は緑）、被弾時に2コマ白く光る、ドロップのアイコンが跳ねる、奥義のカットインは帯の中だけで行う（帯の外にはみ出さない）。画面を揺らす演出はしない。

## 12. セーブ

- パスの定義は `src/main/paths.ts` だけで行う。
  - 利用者：`app.getPath('userData')/save/save.json`
  - 開発：`pnpm dev` と テストでは、プロジェクト直下の `.dev-data/` を使う（`.gitignore` に追加する）。環境変数 `GAME_PROFILE=dev` で切り替える。
- 書き込みは、一時ファイルに書いてから置き換える（途中で落ちても壊れないように）。直前の世代を1つだけ `save.prev.json` として残す（セーブは取り戻せないデータなので、バックアップの禁止には当たらない）。

- `version` を持ち、`migrate.ts` で古い版を読み込めるようにする。読み込みに失敗したら `save.prev.json` を試し、それも駄目なら新規に始めてログに記録する。

## 14. 検証の方針

- ロジック（`src/core`）はVitestで検証する。DOMやElectronを使わずにテストできる形を保つ。
- 表示と操作は実画面で確認する。AGENTS.mdに従い、「ビルドが通った」と「実際に遊んで確認した」を分けて報告する。
- 毎回確認する項目：帯の位置／クリックの透過／ツールチップ／トレイの各操作／終了後にプロセスが残っていないか／セーブの保存先（開発用と利用者用が混ざっていないか）。
- GitHub Actionsは使わない。workflowファイルを追加しない。
