# はぐれものダンジョン：技術仕様

更新：2026-11-01。現行コードと設定を基準にする。プレイヤー向けのルールは [ゲーム仕様](GAME_SPEC.md)、最新の検証結果・未確認事項は [HANDOFF](../HANDOFF.md) を参照。以下の実装説明を、実機受入やSteam本番接続の完了と読み替えない。

## 構成と責務

v0.7.5では`progress/clearRewards.ts`に初回突破判定とボス確定報酬の希少度を集約し、精算と`panel/nextBoss.ts`の予告から使用する。DTOへ各難度の到達値のコピーと所持総数を渡し、既得・最終階・予約先・満杯表示を区別する。

`formationSupport.ts`は解放レベルと実技能IDから回復・守り・自己復活の特徴を生成する。`equipCheck`の構造化された不足属性を`equipmentTraining.ts`が表示し、判定文を解析しない。育成目標はパネル内の一時状態で保存データに追加しない。

`DefeatTracker`はbattle開始を観測した場合だけtick差×REAL_TICK_MSで戦闘時間を計算し、wipe時の生存敵のHPを集計する。`combatMs`と`remainingEnemies`の旧欠落は明示的にnullへ移行し、存在する不正値は拒否する。

`Game.autoFarmState`は同じ壁への再挑戦回数に応じて育成周回を2→4→8へ延長するセッション状態。`recoveryStatus`を両hostの共通view生成へ渡し、画面が独自に周回数を推測しない。手動操作が優先し、保存済みの手動loopとは区別する。再起動時はセッション状態を持ち越さず、通常の3全滅判定から始める。

v0.7.4の接敵は`world.moveAllies`が実座標を移動する。最寄りの敵が自ら接近中なら迎撃し、停止敵に近接が届かない場合のみ`balance.allyAdvanceDotsPerSecond`で隊列全体を同量進める。slot間隔と死者を含む隊列のオフセットを保持し、ウェーブ開始時に戻す。通常攻撃の解決前に標的が死亡した場合は、共有標的選択で射程内の別標的へ1回だけ実行する。

`strip/battleCamera.ts`は実隊列の前進量を補間し、描画・弾・照準・hitTestと既存エフェクトの座標を揃える。ウェーブ座標初期化を逆スクロールにしない。`impactPresentation.ts`は実360msの敵撃破残像（最大8）、実180msの局所会心（最大4）の寿命と形を管理。`scene.ts`が旧スナップショットの死亡を残してから不要visualを破棄し、同フレームの報酬も旧戦場に表示する。シミュレーションへのhit-stopやダメージ変更はない。

`combatLabelGate.ts`は日本語の正規技能名で通常技能と情報表示を制限（同名8秒、全体3.2秒、8秒経過した履歴は破棄）。通知は`battleNotice.ts`が情報/連携/成果/装備/ボス/失敗の順に優先する。通常情報は1秒で消し、古い警告後に再生しない。戦闘境界では旧警告を消し、獲得成果・装備は寿命を保持する。保存復元のtick巻戻りや非表示では全消去する。レア装備は踏破通知にも割り込まれず、ボス予兆が優先された場合は後で表示する。

| 層 | 正本・入口 | 責務 |
|---|---|---|
| ゲームコア | `src/core/` | 戦闘、成長、装備、進行、保存データ検証。Electron・DOM・実時計に依存しない |
| デスクトップホスト | `src/main/` | 時刻駆動、永続化、Windows連携、ウィンドウ、商用サービスの信頼境界 |
| preload | `src/preload/` | 許可した型付きAPIだけを管理画面へ公開 |
| 描画・管理画面 | `src/renderer/` | Canvas戦闘、編成・装備などのUI。共通のShellApiを利用 |
| ブラウザーアダプター | `src/renderer/platform.ts` | Electron APIがない場合だけ共通コアとlocalStorageでShellApiを実装 |
| スマホ入口 | `src/renderer/mobile/` | ブラウザー初期化後に共有管理画面を読み込み、Canvasプレビューと縦画面を提供 |
| 共通契約 | `src/shared/` | API、コマンド、設定、キャラ識別、販売カタログなど |

主な実行環境はElectron 44.9、TypeScript 6、electron-vite 6／Vite 8、pnpm 10。Windowsネイティブ連携にはkoffiを使う。ブラウザー版は同じコアを動かす入口であり、ネイティブのタスクバー常駐・自動起動・保存フォルダー操作を持たない。詳細は [MOBILE](MOBILE.md)。

コアの`createGame`・`advance`・`runCommand`・`buildView`・`snapshot`・`validateProfile`を両ホストで共有する。ゲーム内の乱数状態を保存し、戦闘とドロップの乱数を分ける。時計はホストから渡し、コアが勝手に現在時刻を読まない。

管理画面は`panel/index.ts`が画面状態と操作をまとめ、`dom.ts`が翻訳対応DOM生成、`portrait.ts`が肖像Canvas、`dex.ts`・`store.ts`・`help.ts`が独立した画面を担当する。表示だけの都合をコアへ混ぜず、保存失敗の制御は`main/persistence.ts`の`PersistenceGuard`へ分離する。敵の動き・縮尺・識別は後述の`enemyPresentation.ts`へ集約し、Sceneのイベント処理と役割を分ける。

## 日本語・英語

`src/shared/i18n.ts`が`ja`／`en`、言語変更通知、数値書式、固定文とプレースホルダー文の表示変換を管理する。ゲーム・装備・敵説明は`shared/locales/en-game.ts`、プラットフォームの案内は`en-platform.ts`、システム文と各画面の登録辞書は`system.ts`や`panel/translations.ts`に置く。保存するジョブID・装備ID・イベント・進行値は翻訳しない。

rendererは言語変更で再描画し、Canvasの通知やDOMの文字・属性を表示境界で翻訳する。Windowsは検証済み`Settings.locale`を`settings.json`へ保存し、mainのトレイ／ダイアログとrendererへ同期する。ブラウザーも`hyakkiko.web.save`内のsettingsへ選択を保存する。旧`hyakkiko.locale`は移行入力だけとし、保存成功後に削除する。保存失敗では選択を元へ戻して原因を表示する。初回はOS／ブラウザーの言語を使い、通常画面に言語トグルを置かない。Profileの形式変更やWindows／Web間の自動同期は伴わない。未登録文の日本語フォールバックは翻訳完了の証拠にせず、最終画面確認で漏れ・長さ・属性・動的文を検証する。

UI書体は`renderer/font.css`の`--font-ui`と`assets/fonts/`のBIZ UDPGothic WOFF2へ集約する。400/700の全字形を同梱し、`fonts.ts`で実読込を待つ。欠落・decode失敗は起動エラーとして通知し、OSの代替書体で読み込み成功にしない。外部フォント配信やOSへのインストールは不要。固定出典・ハッシュ・変換方法・OFLは`assets/fonts/README.md`／`OFL.txt`、ライセンス本文はゲーム内Helpからも参照可能。

## キャラ・編成・育成の正本

`core/progress/formationSupport.ts`は編成プレビューの純粋関数を持つ。専用連携の相手関係を技能へ結び付け、名前・説明・効果量は`jobs`、解放レベルは`balance`から取得する。3人が異なること、出撃者と控えの交換であることを検証する。`experienceSupportMultiplier`を実経験値付与とプレビューで共有し、控え・予約中の仲間に経験値が入るという表示をしない。現出撃は`fighting`、交換後は次の編成先頭3人で評価する。選択中候補はpanel内の一時状態に限り、確定時だけ`reorderParty`を発行する。連携カードは必要レベルと発動条件のみを日英で表示し、刻印で変わる威力・再使用時間を重複表示しない。実効値は各キャラの技能欄に集約する。

`src/core/data/jobs.ts`に17ジョブ、表示名、ロール、スキル、編成順を集約する。出撃は先頭3人に限定し、控えを出撃扱いする計算を避ける。経験値の付与先は報酬発生時の実World出撃ジョブ3人とし、次ウェーブ待ちの編成変更や控えへ先行して付与しない。控えを含む17人の既存成長・装備はProfileに保持し、過去のレベル・経験値は減らさない。ジョブ追加時は一覧だけでなく、検証・保存移行・図鑑・描画との対応を揃える。

オフライン対象は`Profile.offlineJobs`に実出撃3IDを保持する。`pendingOffline.expByJob`へ発生時の対象別経験値を固定し、異なる編成期間の報酬合算でも対応を維持する。claim時に現在編成へ再配分しない。旧未受取報酬は保存された実出撃情報、情報がない旧データは旧編成先頭3人を使って一度固定する。`pendingOffline.exp`は互換用の表示値として残す。

`src/shared/characters.ts`は人物ID／ジョブID／外観キーを分離する。改名や衣装追加で人物IDを変えず、同ジョブの別人は別IDとする。現行の仮個人名は公式表示へ自動反映しない。[CHARACTERS](CHARACTERS.md)、[IP](IP.md) に設定と監修状態を残す。

能力値は筋力・敏捷・体力・知力。レベルごと3点、自動配分は主能力6・体力2・その他1ずつの累積配分。振り直しは無料。装備判定はジョブ適合と初期値＋割り振り値を使い、キャラレベル条件を追加しない。再配分時は装備を再検証し、不適合品を安全に外す。装備の`ilvl`は内部性能段階で、装備可能レベルではない。

## ダンジョンと数値の安定性

`core/progress/abyss.ts`が深淵の目標と踏破記録を管理する。`advance`は深淵のstageClear時、報酬によるLv/自動装備変更より前にWorldの実出撃3人を保存する。`Profile.abyssRecords[dungeonId]`へ最高クリアと節目履歴8件を持ち、`ProfileView.dungeon.abyss`で表示する。v3の拡張フィールド欠落だけ空記録へ移行する。present null、不正階、未知ダンジョン、重複ジョブ、不正配分、過大履歴はエラーにし破棄しない。装備は当時の名前を保持し、現在のinventory参照へ置換しない。

実時間集計は`accountElapsed`へ集約。ホストが処理上限で戦闘の追いつきを打ち切る場合も、その実経過を統計へ一度だけ加え、プレイ時間や毎分収入の分母を欠落させない。Web/Windowsとも上限を越えて無制限に追いつかせない。60秒以上の空白は従来どおり別の放置報酬経路、一時停止中は加算しない。

分途中の実経過は`Profile.rates.elapsedMs`（0以上60000未満、開発速度に対応する有限小数可）へ保存し、`rates.current`と一緒に再起動・JSON/クラウド復元をまたいで継続する。Game内に別の分時計は持たない。v3の旧保存で`elapsedMs`だけが欠落している場合、経過が不明な`current`を`legacyUnmeasuredGain`へ明示移行して保持し、新しい測定を0から開始する。旧確定`minutes`・所持金・経験値は変更しない。時間不明の旧途中額は毎分率・放置報酬へ混ぜず、`playMs`から経過時間を推測しない。存在する不正な経過・旧集計・獲得額はエラーとし、移行時の合計が数値上限を超える場合も拒否する。

`src/core/data/dungeon.ts`がダンジョンと難易度を定義する。現行は`yomi`のみ。通常・修羅は100階、深淵のみ上限なしのゲーム仕様。実装では安全な整数の上限を使い、最後の表現可能な階で不正な加算を行わない。

100階以降の強化量は対数を用いて圧縮し、階の深さに比例した巨大ループや指数オーバーフローを避ける。通貨・経験値などの累積値にも有限値・上限の防御を置く。階の一覧は現在地周辺・最初・上限などの必要部分に限定し、到達階数分の配列を生成しない。

Profileは`dungeonId`、`dungeonSeed`、`dungeonRecords`を持つ。各記録は難易度別の到達階・イベント受領地点・現在地・周回・街滞在を保持する。将来の別テイストのダンジョンを既存ダンジョンの増築として混ぜず、独立した進行へ拡張できる。未定義IDや不正な値は読込時に検証する。実装済みの選択可能ダンジョンが複数ある、という意味ではない。

装備は基本値85〜115%の抽選値と追加効果を保持。6希少度、神話固有4系統、所持品上限100。自動装備・売却にもジョブ／能力条件とロックを適用する。ローカル装備の`marketEligible`は常にfalse。

新ドロップの基礎能力は`core/progress/items.ts:rollItem`から`core/data/dungeon.ts:depthScale`を呼び、敵と同じ成長座標を使う。通算ランクを`r = floor + difficulty × 100`とし、安全な整数上限で制限する。`n = min(r,100) − 1 + 20 × log2(1 + max(0,r−100)/20)`に対して、武器の攻撃倍率は`1 + 0.22n + 0.012n²`、防具のHP倍率は`1 + 0.075n + 0.001n²`、防具の防御倍率は`1 + 0.045n`。各基礎値に対応倍率・希少度倍率・85〜115%の抽選値・固有装備倍率を掛けて保存する。ジョブ別武器係数も維持する。敵側だけは別途難易度固有倍率を持ち、装備への二重適用はしない。

旧`1.12^(min(r,60)−1)`を新ドロップの基礎能力には使用しない。装備条件とLUK追加効果に使う`scaledRank`は別責務であり、基礎戦闘能力の曲線と混同しない。`sellPrice`は`floor(cappedAmount(5 × depthScale(r,0).reward × rarities[rarity].sell))`を正本とし、旧1.15の指数を廃止する。`rankGrowth/sellGrowth/deepGrowth`の不要な旧価格定義は削除した。価格は保存しないため既存品にも同じ計算を使う。`validateProfile`は保存済みの`atk/hp/def/affixes/name`を再生成しない。旧装備の性能を保持するため、旧版セーブと新規セーブのバランスが同じになるとは保証しない。

`itemName`は5ランクごとの名称帯を使い、基本名を使い切った後の接尾辞を`改弐`〜`改玖`、続いて`改10`・`改11`…へ進める。名称生成は新しい品に限る。保存済みの日本語名や内部IDを更新時に書き換えない。

## 敵の表示と図鑑

`core/data/bossPatterns.ts`は初期／変化の技能ID、説明、巡回と100階山場の正本。通算50階を解禁条件に、`floor((floor - 50) / 30) + difficulty`の偶奇で型を選ぶ。100の倍数階は初期技→HP50%以下で変化技。`currentBossPattern`を発動・候補・力士の温存判断が共有し、解決時は詠唱開始時のIDを`bossSkillById`で引くため途中のHP変化が既存詠唱を改変しない。混成召喚の化け猫攻撃倍率は各敵の基礎攻撃・二連撃・tick丸め後の間隔から導出する。新しい技能IDを階層数に比例して増やさず、既存2型だけを循環する。

`src/core/data/enemies.ts`を戦闘特性の正本とし、図鑑対象12種と非掲載の分裂片・幻影2種を持つ。`src/shared/enemyGuide.ts`は実際のboss／traitsから役割と攻略文を導出する。`src/renderer/panel/dex.ts`は区域別の図鑑表示を担当し、管理画面本体から分離する。

`src/renderer/strip/enemyPresentation.ts`は整数座標の種別動作、派生の縮尺、通常／強敵／ボスの表示判定、ダメージの整数表示を集約する。分裂片0.6倍・幻影0.8倍を描画・頭上バー・クリック領域へ適用。強敵判定はコアと同じ「10階刻み以外の最終ウェーブ」、ボスは定義で判定する。描画の丸めを戦闘計算へ逆流させない。

通常攻撃の予告表示はSnapshotの`action=windup`とattackイベントの対象IDに同期する。ボス特殊技はコアの`cast`として対象ID・開始位置・解決tickを保持し、`bossTell`と`SnapshotUnit.bossCast`を描画へ渡す。予告中は敵の通常移動を止め、解決時に生存・対象・近接射程を確認する。開始位置から18ドット以上押し戻された場合は`bossInterrupt`を発行し、効果を出さない。再使用待ちは予告開始時に消費する。全滅・街帰還・ウェーブ切替ではactionを消去し、保存からWorldを復元するときに途中の詠唱を再生しない。

力士の張り手は`skills.harite`が前方48ドット内の候補を選び、`cast`中の敵を距離順より優先する。射程内ボスが実際に発動可能で、スキル準備がゲーム内2秒（標準速度では実時間1秒）以内なら張り手を温存する。`core/sim/boss.ts`の`canStartBossSkill`・`canReserveBossSkill`が対象/射程/召喚上限の共通条件を利用する。短い移動・通常攻撃準備は終了予定と技能CDの両方が予約時間内なら温存対象にする。長い移動・射程外・召喚上限では温存しない。待機時間の正本は`jobs.rikishi.skill.params.bossReserveMs`。`actions.pushEnemy`が中断閾値を越えた押し出し元をactionへ記録し、`bossInterrupt.sourceUid/interruptSkillId`で張り手と奥義を区別する。射程・再使用待ち・他の行動中という制約は維持し、描画側から中断を成立させない。

## 探索先・敗北記録の表示

`shared/nextBoss.ts`は`bossEvery`・`areaOf(floor).boss`・`enemies`から次の大ボスを導出し、`enemyGuide`の対処文を再利用する。階層とボスIDの別表は持たない。現在ボス階では同階、移動予約中は予約先を起点とし、通常・修羅の100階制限と安全な整数上限を越える候補を出さない。`panel/nextBoss.ts`をパーティ／迷宮で共用し、日英の要点だけを表示して役割候補は折り畳む。

`core/data/loot.ts:lootTendency`が実階層を`areaOf`へ渡し、区域と装備種別の重みを一元化する。墓地＝防具、商街＝武器、書庫＝お守りの基礎重みを`AREA_LOOT_MULTIPLIER = 2`倍にする。正規化後の確率2倍ではなく、全種類の抽選を残す。神話固有・種類指定の報酬は除外し、既存装備は再生成しない。迷宮UIも同じ定義を参照し、区域ごとに近い到達済み階を定数件の候補計算で求める。無限階層の全件列挙や階層グリッドは作らない。

`DungeonTravelDraft`はパネルセッション内だけの未送信文字列を保持し、ダンジョン／難度の変更で切り替える。送信時は実inputの制約検証と`valueAsNumber`を使い、別の数値closureへ複製しない。`canTravelTo`を区域ボタンとフォームで共有し、街以外の現在階・同一予約の再送を防ぐ。ホストから`selectStage`成功が返った場合だけ`completed`でdraftを消し、失敗や通信例外では保持する。`buildView`は任意の`World.pending`引数から`dungeon.pendingTravel`を生成する。Windows/Web両ホストが実際の予約を渡し、UIは日英で予約先を表示する。入力draftや予約表示用DTOを保存プロファイルへ追加しない。

`core/progress/defeat.ts:DefeatTracker`は現在ウェーブの実出撃者を追跡し、wipeで`Profile.lastDefeat`へ3人分を1件保存する。途中の追跡状態は永続化せず、不明な倒れた順・致命打はnullとして扱う。旧版移行は`lastDefeat: null`、新形式の破損値は検証エラーとする。`lastDefeatResolved`は同じダンジョン・難度の進行／深淵実績から該当階の突破実績を判定し、Viewへ派生値として渡す。UIは「突破実績あり」の記録を折り畳み、敗北後の克服という時系列は推定しない。日英の敵・技能名は既存の共通翻訳を使う。

## 時刻・放置・描画

現在の歩行回復は待ち時間から分離する。`balance.walkRecoveryMs = 1200`を予算とし、1刻みの回復率を`walkHealPerSecond × tickMs / 1000 × ticks(walkRecoveryMs / (1 + moveBonus)) / walkTicks(world)`で求める。待ち時間だけを600msへ短縮し、道場補正と100ms刻みへの切り上げを含む旧版の歩行1回分の回復を保つ。

戦闘の固定刻みはシミュレーション内100ms。標準速度は`core/data/timing.ts`の`GAME_SPEED = 2`を正本とし、Windows・ブラウザーとも実時間50msで1刻み進める（20Hz）。短いポーリングから刻みを積み上げ、1回の追従処理に上限を置く。ブラウザーは1回最大50刻み。大きな時間差を無制限の通常戦闘で埋めず、60秒以上の空白などを放置報酬へ移す。プレイ時間・毎分の報酬記録・放置時間は実時間で扱う。

放置報酬は直近10個の完了した1分記録の平均×経過分×0.5。8時間＋道場最大8時間で制限し、報酬と保存時刻を同じ保存へ反映する。ブラウザーは非表示／pagehide時に一度停止し、復帰／pageshowで一度だけ精算する。停止・街滞在中はブラウザーの放置加算を行わない。プラットフォームごとの復帰経路と再起動時の二重加算は受入検証対象。

描画は共有Sceneとピクセル素材を使い、戦闘更新とは分離する。整数の物理ピクセル倍率で拡大し、DPIやリサイズで輪郭が不安定にならないようにする。停止中も外観・設定変更時には再描画する。17人の通常・被弾・灰色表示を同じ素材対応から生成する。プロファイルの更新を伴わない描画のためにセーブを書かない。

Sceneは受信・描画・復帰・残演出判定の入口で同じ`GAME_SPEED`を適用し、内部の時刻をシミュレーション時間へ統一する。歩行と背景の移動、攻撃の構え／打撃／復帰、被弾、弾道の補間、宝箱演出には共通倍率を適用する。追加の歩行調整は共通倍率を変えず、`gaitTiming`の速度を50→100ドット/ゲーム内秒、歩行待ち`balance.walkMs`を1200→600msへ変更する。標準速度かつ道場補正なしの実歩行待ちは0.3秒。戦闘中の移動・攻撃・スキルの時計は追加加速しない。通常の説明バナーや設定UIの操作時間は可読性を保つため実時間のままとする。開発用の歩行／シーン比較も同じ倍率を使い、比較カードの時刻は実時間で表示する。

読み取り用のダメージ数字は通常580ms・会心等760msの実時間を確保し、最大30個と空き領域への配置を維持する。命中の白フラッシュは実65ms、敵の局所停止は実45ms。同じ対象の命中強調は実160ms以上の間隔を空け、連続攻撃で白表示や停止を延長し続けない。この命中強調の調整では攻撃動作・移動速度・ダメージの処理頻度は変えない。地面装飾と背景は同じ`battleSurfaceWidth`で幅を制限し、コンパクト画面は全面、横長のデスクトップはパーティー付近だけを描く。

攻撃間隔・技能の再使用時間は`core/sim/time.ts`の`realTickSeconds`で戦闘と同じ固定刻みへ切り上げ、実秒へ換算する。装備比較も同じ変換を行い、同じ刻みに収まる差には改善／悪化の矢印を出さない。すでにtickから算出したボス詠唱残秒や技能の継続時間は`realSeconds`で実秒へ換算する。技能の継続時間は日英の説明に`{duration}`を置き、`skillDescription`が戦闘で使う`params.ms`から埋める。説明文に秒数を二重定義しない。再使用時間は装備補正と固定刻みへの切り上げを含め、保存する戦闘能力の値自体はゲーム内時間を維持する。

## 保存場所とデータ保護

デスクトップのパス正本は`src/main/paths.ts`。機能ごとにAppDataやファイル名を再定義しない。

| データ | 分離と用途 |
|---|---|
| 製品の利用者データ | ElectronのuserData以下。進行・設定・本番の販売状態 |
| 開発データ | プロジェクトの`.dev-data`。利用者データへ混ぜない |
| 明示した検証用データ | `GAME_DATA_DIR`で独立した場所を指定 |
| `save.json` | 現行の進行 |
| `save.prev.json` | 有効な前世代の進行 |
| `save.broken.json` | 復旧が必要な壊れた進行。別の破損データで無断上書きしない |
| `settings.json` | ウィンドウ・音・表示など |
| `commerce.json`／`commerce.sandbox.json` | 本番とテストの取引・権利を分離 |
| ブラウザー | 単一キー`hyakkiko.web.save`。端末内保存はWindowsと別。クラウドの同一アカウントで手動転送できる。Steam保存とは未連携 |

Profileの現行JSON版は3。旧版1・2を検証して移行し、3では能力配分・ダンジョン別記録などを保持する。存在しないメンバーや不正な数値・装備参照をそのまま実行状態へ持ち込まない。対応版より未来の保存を「破損」扱いで初期化しない。

`saveStore.ts`は一時ファイルへ全量書込→fsync→close→renameで主ファイルを置換する。置換前に有効な主ファイルから前世代を原子的に更新する。壊れた主ファイルを正常な前世代へ上書きせず、復旧では元の正常バックアップを保持する。書込完了後にだけメモリー上の保存時刻を更新する。

主・前世代と途中書込ファイルに未来版がある場合は`FutureSaveVersionError`で止める。現在版の古いバックアップへ勝手に戻して未来版を消さない。両世代が不正な場合や既存の破損退避を保護すべき場合は`SaveRecoveryRequiredError`で停止し、起動側で日本語の案内を出す。新規データ作成は本当に保存がない場合に限る。

Windowsの`PersistenceGuard`は書込例外を保持し、`ShellState.storageError`を通知、ホストを一時停止して管理画面を開く。エラー中はゲームコマンドと通常の自動再保存を止め、明示した`retrySave`でだけ保存を再試行する。成功はエラーを解除するが、自動再開しない。`exportSave`は利用者の保存ダイアログで選んだ別ファイルへ、メモリー上の進行を書き出す。

`before-quit`でも保存結果を検査し、失敗時はゲームへ戻る／書き出す／保存せず終了の選択肢を表示する。最初の二つは終了を取消し、最後を明示選択した場合だけ未保存の終了を許す。パネルを閉じる操作は常駐を保つため、終了処理と混同しない。設定や販売状態の書込もそれぞれの呼出し側で失敗を扱い、進行保存が成功しただけで全保存が成功したとはみなさない。

ブラウザーは`{format:1, profile, settings, state:{paused}}`を単一setItemで保存する。未来版・不正JSON・読込不能時はエラー画面で停止し、元データを書き換えない。容量超過・書込失敗は`storageError`を通知して進行を止める。最後に読んだ生データとの比較とstorageイベントで、別タブによる更新を古い状態で上書きすることを防ぐ。JSON書き出しは利用者の操作時だけ実行する。クラウドへの保存・復元も利用者が明示操作し、自動同期は行わない。

ブラウザーの`retrySave`はfalseを返す。競合検知後に古いメモリーを強制保存して別タブの新しいデータを失わないよう、書き出し→再読込を案内する。終了時のnativeダイアログは提供せず、pagehideのベストエフォート保存とエラー表示を利用する。OSやブラウザーによるタブ強制終了まで保存完了を保証しない。

### JSON取り込みと起動時の明示復旧

`shared/saveImport.ts`の`SaveImportSession`が候補の検証・事前構築・確認tokenを保持する。`MAX_SAVE_IMPORT_BYTES`（1MiB）をrendererのファイルサイズ検査とホストのUTF-8バイト数検査で共有する。`prepareSaveImport(text)`はJSON解析、共通の`validateProfile`と`prepareCloudRestore`によるオフライン報酬計算、Game構築を済ませ、保存日時・難度・階・小判・プレイ時間・出撃3人を返す。書込みはしない。候補は一つだけで、選び直しで古いtokenを失効させる。

`confirmSaveImport(token)`は現在の保存／runtime障害・終了状態を再確認してから候補を保存し、実行状態へ置き換えて一時停止する。Windowsは既存の原子的保存とチェックポイント管理、ブラウザーは生データ一致の検査と単一`setItem`を利用する。確認tokenは使い切りで、失敗後に勝手に再送しない。`cancelSaveImport(token)`は候補を捨てるだけで現在の進行を書き換えない。JSONの原ファイル、設定、購入した外観を正常時の取り込みで変更しない。

`panel/saveImport.ts`がファイル選択・確認画面・処理中ガード・原因を残すalertを担当し、通常設定画面と起動復旧画面が同じ実装を使う。確認画面は`PanelModalFocus`でオフライン報酬と同じ背景inert・Tab制御・フォーカス復帰を使い、取り込みではEscapeで取り消せる。オフライン報酬と取り込み確認を同時に開かない。

ブラウザー起動時の破損は、ゲームループを開始せず原因表示を保持したまま`browserSaveRecovery.ts`へ渡す。ここでは現在の生データが読み取り時と同じかを確認し、検証済み進行と初期設定・一時停止を明示確認後に一括保存してページを読み直す。設定を信頼できない経路なので、OS／ブラウザー由来の初期言語で設定を再作成することを先に説明する。既存保存の未来版、保存領域の読取失敗、確認中の別タブ更新、容量不足では上書きを拒否する。保存キー・包絡形式は`shared/browserSave.ts`へ集約する。

これらは実装仕様であり、単体試験・IAB操作・Windows実exeで確認した範囲の正本は[VALIDATION](VALIDATION.md)と[HANDOFF](../HANDOFF.md)。本節だけで実スマホやネイティブの全復旧操作を合格とは扱わない。

## IPCとWindows連携

Electronのrendererはsandbox／contextIsolationを有効にし、nodeIntegrationを無効にする。preloadで公開するShellApiのコマンド・設定・対象IDをmain側でも解析する。rendererから任意のファイルパス・任意コード・実決済結果を受け取って信用しない。

タスクバー帯、クリック透過、表示領域、全画面検出、自動起動などはデスクトップ層へ閉じる。全画面検出ではデスクトップ／タスクバーのシェルウィンドウを除外し、検出失敗や停止時に非表示状態を残さない。D3D状態・複数画面・DPI・全画面ゲームとの実機互換性はロジックテストだけで保証しない。

## 外観・決済・Steamの境界

詳細は [COMMERCE](COMMERCE.md)。本体買い切りと能力差のない外観販売の方針。カタログのテーマを30秒試着できるが、試着は購入権利を付与しない。通常ビルドの購入機能とブラウザーのストアは利用不可で、実課金要求を送らない。Steam SDKの本番アダプターは未接続、マーケット機能はfalse。

購入テストは開発中・未パッケージ・明示フラグの条件でのみ有効にする。テスト所有権を製品へ移行しない。本番価格は検証済みプロバイダーの返答を必要とし、仮価格を本番の請求金額として使用しない。

取引は信頼できるmain側で管理する。送信前にpendingを永続化し、アプリ・アカウント・注文・商品・receipt IDを結び付ける。重複receiptや別注文・別アカウントへの流用を拒否する。タイムアウトや確認不能はunknownとして保持し、自動再送しない。再起動後の未確定取引も再購入扱いにしない。

Ed25519署名検証は独自の信頼された取引サーバー用の境界実装であり、SteamネイティブのInventory署名に対応したという意味ではない。秘密鍵をアプリへ含めない。所有権同期・返金／取消反映・unknown照合・本番の注文発行／確定は未完成で、実販売を有効にする条件を満たしていない。

SteamPipe設定は`steam/build_app.vdf`と`steam/depot_windows.vdf`。APP_ID／DEPOT_IDは明示プレースホルダー、Preview=1、SetLiveは空。実ID未設定の投入を行わず、登録・送信・公開をローカルビルドに結び付けない。Steam契約・ストア審査・税務／銀行・署名などは [RELEASE](RELEASE.md) に区別する。

## v0.5.1の背景・アクション・テンポ

背景原本は`assets/sprites/art/dungeon-backgrounds.png`。本プロジェクト用に組み込みimage_genで生成した3区域分の画像で、生成記録は`assets/sprites/art/PROMPTS.md`に残す。`src/renderer/strip/background.ts`で採用画像の区域境界と床位置を指定し、384×80の内部パノラマへ正規化する。階層と区域の対応を共通のダンジョン定義から求め、歩行量に応じて壁を床より遅く動かす。元PNGは書き換えない。

`Scene.groundBand`／`Settings.groundBand`が背景と地面の表示を共に制御する。Windowsの横長表示は戦闘部分だけの幅と高さへクリップし、右端を段階的に透過させる。コンパクトなスマホ戦闘面は全幅を使用する。OFFでは背景・地面の帯を描画せず、Windowsの透過ウィンドウを維持する。設定文は日英で「背景と地面を表示」／「Show background and ground」。

`actionPresentation.ts`にジョブ別の構え・踏み込み・上下動・伸縮・戻りを集約する。斬撃、突き、拳、掌打、投擲、術、跳躍、扇、本の型を使い分け、Sceneが命中時の短い停止・閃光・反動・impactを描く。飛び道具の命中で投げ動作を再生し直さない。表示の演出時間と攻撃の権威ある判定を分離し、描画だけでダメージを重ねて適用しない。

歩行は`gait.ts`と専用PNG3枚（全17人×5コマ）で管理する。地面の移動距離を唯一の時計とし、ゲーム内毎秒100ドット／1周期40ドット／5コマ=12.5fps（共通2倍時計では実毎秒200ドット・25fps相当）。以前の50ドット・6.25fpsから歩行と背景を同時に2倍化する。ジョブ・隊列で位相をずらし、跳躍・重い横揺れ・小刻みな歩きを分ける。各人物の5コマには同じ拡大率を使い、コマごとに身体を拡大縮小しない。個別セルの境界内で切り出し、隣コマへ繋がる透明余白を含む拡張は行わない。Scene.pausedはWindows／mobileの状態から渡し、停止時は地面と歩行位相を固定する。`/qa-walk/`はVite開発時だけの実素材確認ページで、製品buildの入口には含めない。

敵の待機キーは`assets/sprites/art/enemy-atlas.png`、新規攻撃キーは`assets/sprites/art/enemy-attack.png`。いずれも同じ12種に対応する4列×3段で、待機12姿／攻撃12姿のPNG2枚として管理する。攻撃キーもimage_genで生成し、元の敵と同じ存在として素材IDと外観を対応させる。実行時はidle／attackキー切り替えに種類別のbody motionを加える。背景PNG1枚・3区域は別の描画資産として扱う。

後列近接が射程外のまま棒立ちになる問題は、味方の通常近接攻撃の射程判定を生存前衛の`home`基準へ揃えて解消する。表示座標だけを後列→対象の敵前→打撃→自分の`home`復帰と動かし、論理`home`やaggro計算を動かさない。敵の通常射程、味方の遠距離攻撃、スキルの射程、ダメージ倍率は維持する。判定対象の前衛と現在の生存状態を基準とし、画面上のダッシュ距離を追加の攻撃倍率へ流用しない。

v0.5.1時点の調整履歴：テンポ定義は`src/core/data/balance.ts`。当時は歩行4000→1200ms、waveClear1000→300ms、stageClear2000→800ms、wipe3000→1800ms、bossIntro1500→900ms、spawn200→100ms、windup200→100ms、projectile240→360ドット/秒。味方の通常攻撃間隔に0.5倍を適用し、能力欄にも同じ値を渡す。敵の攻撃間隔・スキルCDは変更しない。歩行回復は0.02→0.065/秒として、歩行1回の回復量を約8%へ揃える。旧版の性能・進行測定は履歴として残し、v0.5.1の測定として流用しない。最新版の受入結果はHANDOFF／VALIDATIONを参照する。

## v0.6のクラウド保存と責務

クラウドサービスはゲームと別のGitリポジトリ `C:\00_PG\40_game_test_server` に置く。ゲーム側は`src/shared/cloud.ts`でコマンドと表示用メタデータを定義し、`cloudClient.ts`が認証、HTTP応答の形式検査、リビジョンの整合性、10秒の通信期限を担当する。`view()`はメモリー内の状態を読むだけでHTTP通信しない。`execute()`だけが利用者の明示コマンドに対応する通信を行い、同時操作と自動再送を行わない。

Windowsではmainの`CloudClient`から通信し、preloadの許可された`getCloud`／`cloudCommand`だけをパネルへ公開する。ブラウザーでは`platform.ts`のアダプターが同じクライアントへ接続する。パネルの`cloud.ts`は認証フォーム、処理中表示、結果とエラーの翻訳、読込前の確認を担当する。サーバー保存が未確認の`revision:null`と、確認済みで保存がない`revision:0`を分け、未確認状態でupload/downloadしない。

接続先の正本はWindows起動時の`GAME_CLOUD_URL`とブラウザー開発／ビルド時の`VITE_CLOUD_URL`。開発時だけ`DEVELOPMENT_CLOUD_ENDPOINT`のloopbackオリジンを使う。本番で値が未設定なら未接続とし、稼働しているように見せない。HTTPSオリジン、またはローカル開発用のloopback HTTPだけを許可し、資格情報を含むURLやパス・query・fragment付きURLを拒否する。ブラウザーはVite設定で対象オリジンをCSPへ追加し、サービス側の`CORS_ORIGINS`にもブラウザーのオリジンを明示する。外部公開や遠隔HTTPSの運用は別の受入条件とする。

認証セッショントークンはクライアントのメモリーだけに保持する。パスワードは送信後にフォームから消去し、ゲームのセーブ・設定・localStorageへ保存しない。再起動後は再ログインする。アカウント別に進行セーブを一つ持ち、アップロード時は取得済みrevisionを`baseRevision`としてサーバーの現在値と比較するCASを使う。他端末の保存と競合したら409で拒否し、古い状態を自動で押し込まない。結果不明のuploadはrevisionを未確認へ戻し、利用者が最新状態を確認するまで再保存できない。

同期は手動で、設定・外観ストアの所有権やSteam取引状態を同期対象に含めない。読込は対象revisionを固定した2段階確認後にGETし、確認時から版が変わっていたら拒否する。取得profileはゲームのvalidatorを通し、ローカル保存が成功してから実行中のゲームへ反映する。保存失敗時は元の実行状態を保持し、保存障害を表示する。正常復元後は一時停止する。未知のサーバーエラー本文は原文を保持し、既知の状態説明とHTTPエラーの周辺文だけを表示層で翻訳する。既知のAPI error.codeには日本語の説明を付け、診断用の元メッセージも保持する。

## 装備比較・演出・通知音の責務

`data/itemNames.ts`を装備の和英名・名前段階・改の境界の正本とする。`data/skillEngravings.ts`は抽選率・倍率・適合パラメータ・説明を管理し、通常技能の実効パラメータを`effectiveSkill`で生成する。戦闘処理と説明文で同じ値を使い、残CD表示はsnapshotの実際の残tickから計算する。保存は刻印IDだけを保持し、武器・希少度・ジョブ適合を検証する。

刻印の種類が変わる装備比較は`skillTradeoff`としてbefore/afterの説明を返し、総合deltaは返さない。同じ刻印同士は通常の評価差を返す。新着案内と一覧は共通の優先順を使い、通常改善は評価差順、その後に有意な刻印選択を置く。刻印を失うだけで他の能力が改善しない弱い普通品は新着案内から除く。通常の総合評価は正の加重倍率で算出し、長CDによって攻撃力増加が負評価に反転する式を使わない。

`renderer/battleNotice.ts`はWindowsとブラウザーで共通の通知優先制御を担う。敗北・ボス予兆を通常技能やドロップで即時上書きせず、待機通知は重要な一件まで。ボスの技が発動・中断すると予兆を即時更新する。非表示時は通知を消去し、`VisibleFrames`で非表示中の演出を再生しない。

`sourceArt.ts`は原本decodeと切出しを共有する。管理パネルは6枚の原本から29portraitだけを読み、歩行・攻撃・背景は読み込まない。戦闘側は`art.ts`／`sheet.ts`で必要なanimationを生成する。mobileの同一realmでは同時decodeとportrait canvasを共有し、完了済み原本Imageをcacheに保持しない。原画や切出し寸法は変更しない。`VisibleFrames`は帯を隠した間の描画を止め、再表示時は最新snapshotから局所演出をリセットして再開する。シミュレーション・保存は描画とは独立して継続する。

実行時異常は`runtimeFailure.ts`と`GameHost.attempt`の境界で原因を保持して停止する。mainはruntimeError中のコマンド・自動保存・終了時保存・遅延したcloud復元を拒否する。明示的な読み直しだけが復旧checkpointへ戻し、停止状態で開く。起動時とsleep復帰のoffline報酬は通知前にcheckpointへ含め、保存失敗では元ファイルとsavedAtを保つ。保存の失敗と実行時異常、音の失敗はそれぞれ別に表示する。

装備評価は`core/progress/items.ts`の`compareEquipment`へ集約し、自動装備と表示用比較が同じ前後能力を使う。`buildView`は呼出内だけ`createEquipmentComparison`を生成し、17名の現在装備・変更前能力・属性を再利用して各品の適格判定を一度行う。永続キャッシュは使わず、次回の表示作成では装備交換・ステ振りを反映する。`buildView`は変化した能力だけを送信し、rendererが評価計算を複製しない。`panel/equipmentComparison.ts`が増減と単位を表示し、`nextChoice.ts`が未確認の出撃者向け装備へ案内する。新着を時間だけで確認済みにする処理は廃止した。

日英ヘルプは`helpContent.ts`の同一構造データと`help.ts`の単一描画処理を使う。通知音は`audio.ts`がWeb Audioと回数制限、`audioSession.ts`がホスト状態・入力操作・ページ復帰・終了を管理する。`audioNotice.ts`は原因を保持した独立表示を担当する。保存エラーや戦闘バナーで音の障害を消さない。

ボスの対象と解決tickはシミュレーションが確定し、Snapshot/SimEventで描画へ渡す。rendererは予兆と残り時間を表示し、命中判定や中断条件を再計算しない。`/qa-scene/`は製品と同じSceneへ固定イベントを渡す開発専用比較ページであり、製品buildの入口に含めない。合成画像は実進行の証明と区別する。

敵と装備の進行尺度は`progressionDepth`で共有し、表示する階数と内部の難易度通算を分離する。通常B1〜100の敵成長は維持し、新ドロップの基礎能力だけ上記曲線へ修正した。上位難度の開始時に装備品質と敵強度が巻き戻らない。[実進行の検証記録](reviews/2026-10-29-progression-validation.md)では、固定装備の編成比較と実際のドロップを使う進行測定を区別する。

表示名称は`shared/brand.ts`で管理する。互換性のため既存のAppDataフォルダー・アプリID・実行ファイル名・保存キーは変更しない。

## ローカル検証と配布

すべてローカルで実施し、GitHub Actionsは使用しない。複数変更の途中は関連単体だけを確認し、一連の変更がまとまった最後に全体検証を行う。

```powershell
pnpm typecheck
pnpm lint
pnpm test
pnpm test:shell
pnpm sim
pnpm build
pnpm web:build
pnpm dist
pnpm release:check
```

`pnpm dev`は開発用起動、`pnpm sprites:preview`は素材確認。`vite.web.config.ts`はmobileだけを入口にし、相対URLのWeb生成物を`dist/web/`へ出力する。`pnpm web:dev`は5174、`pnpm web:preview`は4174でlocalhostへ提供する。LAN内スマホの確認では明示的に`--host 0.0.0.0`を渡す。入口・終了手順と保存オリジンの違いは [MOBILE](MOBILE.md) に従う。外部公開は行わない。

配布先は`release/`、Windows portableは`TaskbarHyakkiko-<version>-portable.exe`。`dist`はアイコン生成、renderer/main/preloadのビルド、electron-builderのportable生成を行う。配布にはビルド成果物と必要なWindows x64ネイティブ依存を含め、開発データや認証情報を入れない。

`tools/release-check.mjs`はアプリ本体のPE/x64、NSIS起動部のWindows PE、asarの必須ファイルと版、koffiのWindows x64依存、禁止データ混入、既知の秘密情報パターンを検査し、配布物のSHA-256一覧を`release-manifest.json`へ出す。NSIS起動部はx86でも内部の本体はx64であるため、二つのmachine値を別々に記録する。未知の秘密情報を完全検出する保証や、署名検証・実行試験の代替にはしない。

本書の更新だけを理由にテストやビルドを実行しない。**最終検証は [HANDOFF](../HANDOFF.md) 参照。** 型・単体・ビルド・ファイル検査の成功と、Windows実exe、クリーンPC、長時間放置、全画面、DPI、スマホSafari／Chrome、実決済・Steam受入の成功を分けて記録する。性能の目標は10Hz進行を阻害せず、深い階でも無制限な配列や追従処理を増やさないこと。実測していないCPU・メモリー・電池・端末互換性の数値は保証しない。
